# Calendar image export — October 16, 2026

Calendar sharing and Save Image are implemented on main. The saved scene and permanent scene builder contain the working header controls; no manual wiring is required. `HANDOFF.md` remains empty.

The subsequent [October 22 full-screen alarm update](FULL_SCREEN_ALARMS.md) records the current APK and intentionally adds full-screen alarm access. The APK permissions, validation counts and hashes below describe this earlier export build.

## Use

Navigate to the desired month and tap **Share** beside the family filter. ShiftCal generates the image locally and opens **Share ShiftCal Calendar**, Android's native chooser. Choose any installed PNG-compatible destination and complete the send there. Opening or canceling the chooser never reports that a message was sent.

The small arrow beside Share opens a compact menu with **Share calendar** and **Save image**. On Android 10+, Save Image publishes to **Pictures/ShiftCal** through MediaStore. Android 8–9 use the system Save As dialog. Canceling that dialog reports cancellation. On Android 10+, repeated saves of an identical PNG reuse the recent saved image when its bytes still match; changed calendars or externally edited images produce a new image rather than overwriting an older export.

## Image and privacy

Exports are opaque **2100 × 2460 PNGs**, named like `ShiftCal-November-2026.png`. A separate world-space Canvas and orthographic camera render the image directly at its output resolution. The main screen is never captured or resized. Temporary objects have no raycaster, are spatially isolated, and are released along with GPU/CPU textures in `finally`; the previous active render target is restored.

The image contains the displayed month/year, weekday headings and the same 42 visible dates generated by `CalendarGenerator`. It preserves rotation anchors, custom shifts/colors, date overrides, adjacent-month dimming, shared-note indicators, recurring activity icons, assignment colors and overflow counts. Everyone, Mine, individual-person and Unassigned filters use `ActivityResolver` and the existing family identity behavior. Non-Everyone exports label the activity filter. Work shifts always remain visible.

An allowlisted export snapshot supplies the renderer. It contains no worked-hours values, monthly totals, private alarms/rules, snooze/dismiss state, account IDs, authentication data or preferences. Personal information has no inclusion toggle in this version. The renderer never uses `CalendarDayCell.Bind`, `DayInformation.Resolve`, effective alarm snapshots or a screen screenshot. Notes appear only as shared-note indicators. App controls, selection outlines, today highlights, previews, popups and debug/status overlays are absent.

Export reads cached calendar data and does not call save/sync methods. It works offline and does not write Firestore, change the filter/month, or clear Edit Mode selection.

## Android integration

The existing non-exported FileProvider and `${applicationId}.shiftcal.files` authority are reused. Its XML adds only `shiftcal-calendar-images/` under app-private cache. Native code validates the canonical parent directory, PNG signature, image bounds and size before accepting a file. Sharing uses ACTION_SEND, `image/png`, EXTRA_STREAM, explicit PNG ClipData and a temporary URI read grant on both the send intent and chooser. A narrow image/png intent query supports the no-compatible-app case. No destination is hardcoded and no file:// URI is sent.

Unique cache files avoid replacing an image that another app is still reading. Cleanup retains recent transfers, expires files older than 48 hours on subsequent export, and trims older-than-one-hour entries toward 32 files while protecting the current export. Files remain app-private; recipient access uses Android's temporary per-URI grants.

MediaStore uses IS_PENDING until copying completes, then publishes the image. Failure removes the pending row. An app-private bounded map of recent content hashes avoids repeated identical gallery saves. The older system-document workflow writes only the user-selected content URI and attempts to remove an incomplete newly created document on failure. No broad storage or media-read permission is added. Native image code does not use the alarm store, scheduler or delivery ledger.

This follows Android's [sharing guidance](https://developer.android.com/training/sharing/send), [MediaStore scoped-storage workflow](https://developer.android.com/training/data-storage/shared/media), and [system document creation workflow](https://developer.android.com/training/data-storage/shared/documents-files).

- `Core/CalendarExportSnapshot.cs`: privacy-safe calendar projection using existing generators/resolvers.
- `UI/CalendarExportRenderer.cs`: isolated high-resolution PNG renderer and resource cleanup.
- `UI/CalendarImageExporter.cs`: one-tap export, compact actions, progress/result messages and native callback.
- `Editor/ShiftCalSceneBuilder.Agenda.cs`, `ShiftCalSceneBuilder.Family.cs`, saved `Assets/Calendar.unity`, generated share/save sprites: permanent UI integration.

- `Editor/CalendarExportChecks.cs`, existing focused/runtime/capture entry points, and native `CalendarImageTest.java`: verification.

No saved-data schema, signing credentials, package ID, Firestore policy, alarm definitions or delivery-ledger format changes are required. Production Firebase is untouched.
